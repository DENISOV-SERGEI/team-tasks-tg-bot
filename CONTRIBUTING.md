# Участие в разработке

## Требования

- Python 3.10 или новее.
- Windows или Linux-среда с доступом к Telegram Bot API.
- Отдельный тестовый токен Telegram-бота.

Не используйте рабочий токен или производственную базу данных при разработке.

## Подготовка окружения

Windows:

```powershell
cd VPb06
.\venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Откройте `.env` и задайте собственный тестовый `TELEGRAM_BOT_TOKEN`. Для
изолированных данных можно указать другой путь в `TASKS_DB_PATH`, например:

```dotenv
TASKS_DB_PATH=test_tasks.db
```

Не добавляйте `.env`, базы данных SQLite, резервные копии и виртуальное
окружение в Git.

## Запуск

```powershell
python main.py
```

Один экземпляр бота достаточно для одного токена. Для остановки используйте
`Ctrl+C`.

## Тестирование

Перед отправкой изменений выполните полный набор тестов:

```powershell
python -B -m unittest discover -s tests -v
```

Новые обработчики или бизнес-правила должны сопровождаться узкими тестами:

- доменная логика — без Telegram и реальной сети;
- SQLite — только во временных файлах;
- Telegram-хендлеры — через aiogram Dispatcher или записи запросов;
- сетевые ошибки — только через тестовые mock-объекты;
- пароли, токены и реальные идентификаторы — не добавлять в тестовые данные.

## Правила изменений

1. Сохраняйте слоистую структуру: `ui -> core <- driver`.
2. Не размещайте aiogram, SQLite-драйверы или файловую инфраструктуру в `core/`.
3. Инициализацию БД и polling выполняйте только в точке входа.
4. Не логируйте токены, пароли прокси, строки с секретами и персональные данные.
5. Не копируйте SQLite-файл обычным файловым копированием во время работы бота.
6. Форматируйте сообщения и импорты в стиле уже существующего кода.

## Отправка изменений

- Создайте отдельную ветку для изменения.
- Сделайте небольшой набор связанных коммитов.
- В описании коммита или Pull Request укажите цель и способ проверки.
- Перед публикацией проверьте итоговый diff:

```powershell
git diff --stat
git diff
git status --short
```

- Проверьте, что команды из `.gitignore` исключают `.env`, `tasks.db`,
  резервные копии БД и `venv/`.
